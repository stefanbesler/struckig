Online trajectory generator for multiple DoFs. Call the function block cyclically to generate smooth, time-optimal motion under position, velocity, acceleration, and jerk limits.

Typical cycle:

  1. Set current state, target state, and limits.
  2. Call the function block every PLC cycle.
  3. Use NewPosition, NewVelocity, NewAcceleration, and NewJerk as command values.
  4. Optionally call PassOutputToInput or enable EnableAutoPropagate for state propagation.
otg(
  CycleTime := 0.001,
  Dofs := 2,
  ControlInterface := ControlInterfaceType.Position,
  Synchronization := SynchronizationType.TimeSync
);

IF otg.State = TrajectoryState.Busy THEN
  Axis1.Setpoint := otg.NewPosition[0];
  Axis2.Setpoint := otg.NewPosition[1];
END_IF

Duration 

PROPERTY Duration : LREAL

Total planned trajectory duration in seconds. The value is set after successful calculation and remains valid until inputs change or Reset is called.

In synchronized operation this is the common duration for all participating DoFs.

Property Value

LREAL

State 

PROPERTY State : TrajectoryState

Current state of the trajectory generator.

  • Busy: active trajectory is running.
  • Idle: trajectory reached end state.
  • Error: invalid input or unsynchronizable profile.

Check this property to decide whether to continue commanding setpoints, hold final values, or handle a fault.

METHOD AtTime (

Gets the kinematic state at absolute trajectory time t. This method evaluates the active profile sections and returns position, velocity, acceleration, and jerk for each configured DoF.

For t >= Duration, the final state is extended with constant acceleration behavior. For single-axis access without vector pointers, see AtTime1.

PassOutputToInput 

METHOD PassOutputToInput ()

Copies NewPosition, NewVelocity, and NewAcceleration to the corresponding current-state inputs. This helper connects one cycle output to the next cycle input and is useful in closed-loop PLC applications.

Equivalent to manually assigning:

CurrentPosition := NewPosition;
CurrentVelocity := NewVelocity;
CurrentAcceleration := NewAcceleration;

Reset 

METHOD Reset ()

Resets the instance (e.g. to force a new calculation on the next update). This method can be used to trigger a new trajectory even if inputs do not change. Use this when external state jumps occur (manual jog, homing, drive reset) and the generator must reinitialize from the new measured state.

ValidateInput 

METHOD ValidateInput (
 [input] checkCurrentStateWithinLimits : BOOL,
 [input] checkTargetStateWithinLimits : BOOL) : BOOL

To check that Struckig is able to generate a trajectory before the actual calculation step,

ruckig.ValidateInput(input, currentState: FALSE, targetState: TRUE);
// returns boolean

returns FALSE if an input is not valid. The two boolean arguments check that the current or target state are within the limits. The check includes a typical catch of jerk-limited trajectory generation: When the current state is at maximal velocity, any positive acceleration will inevitable lead to a velocity violation at a future timestep. In general, this condition is fulfilled when

Abs(acceleration) <= Sqrt(2 * max_jerk * (max_velocity - Abs(velocity))).

If both arguments are set to true, the calculated trajectory is guaranteed to be within the kinematic limits throughout its duration. Also, note that there are range constraints of the input due to numerical reasons, see below for more details.

Recommended usage before applying new targets:

IF otg.ValidateInput(TRUE, TRUE) THEN
  // inputs are valid, call cyclic calculation
  otg();
ELSE
  // inspect otg.ErrorCode() and otg.ErrorMessage()
END_IF

checkCurrentStateWithinLimits BOOL
checkTargetStateWithinLimits BOOL

Returns

BOOL
